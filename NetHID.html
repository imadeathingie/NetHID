ENCODERS
Edits apply the moment you make them — the keyboard is already using them, nothing is flashed yet. Save to flash makes them survive a power cycle; it parks the USB stack for about a tenth of a second while the sector is erased, so the host will see the keyboard go quiet very briefly. Layers above the ones your firmware was compiled with start out transparent, so you can add a layer without masking the one underneath it.
MACROS
Steps run on the keyboard itself, so a macro key works with no browser open. tap presses and releases; hold and release are the two halves of that, for holding a modifier across several steps. Anything still held when the macro ends is released for you. text goes through the same typer the web UI uses, which drives the USB endpoint directly — so modifiers you are holding do not apply to it, and a physically held key is let go for its duration. Assign a macro to a key with the KB_MACRO(n) type in the key picker.

Changes take effect immediately; Save to flash makes them survive a power cycle. A setting you never touch keeps following the value compiled into config.h, so a later rebuild still moves it — only fields marked set are pinned.

Options that decide what gets compiled — the web server, the TCP socket, HTTPS, IR/RF, the keyboard itself — are not here and cannot be. A runtime toggle cannot un-link code, and a button that disables the web server from inside the web server has exactly one effect. Authentication is compile-time for a related reason: one session should not be able to remove the need for the next one.
